# TheHive + MISP + Elastic Lab

This lab deploys TheHive for ticketing and incident workflow, MISP for threat intelligence, and Elasticsearch for the data layer. It is intentionally staged as a teaching lab, so the configuration favors readability and a clear startup sequence over production hardening.

## What is included

- TheHive on port 9000
- MISP on port 8082 and 8444
- Elasticsearch on port 9230
- Kibana on port 5630
- MailHog on port 8025
- Config files, bootstrap helpers, and sample payloads

## Before You Start

- Make sure Docker and Docker Compose are available.
- If you previously ran the MISP lab, stop it first so port 8082 is free.
- On Linux, Elasticsearch may require `vm.max_map_count=262144`.

```bash
sudo sysctl -w vm.max_map_count=262144
```

## Quick Start

```bash
cd thehive/lab
chmod +x scripts/*.sh backup/*.sh
sudo docker compose pull
sudo docker compose up -d
```

Open these URLs after the stack is healthy:

- TheHive: http://localhost:9000
- MISP: http://localhost:8082
- Kibana: http://localhost:5630
- MailHog: http://localhost:8025

## First Login Flow

1. Open MISP and complete the initial setup.
2. Copy the MISP API key from the Automation page.
3. Put the key into `MISP_API_KEY` in `.env`.
4. Restart TheHive so it can read the key from `application.conf`.
5. Log into TheHive and verify the MISP connector is active.

## Operational Exercises

- Create a case with tasks such as `Investigate logs` and `Contain threat`.
- Add observables like suspicious IPs, domains, or hashes.
- Create a MISP event and verify that it syncs into TheHive as an alert.
- POST a custom JSON alert to TheHive's API with `scripts/submit_alert.py`.
- Run `scripts/perf_load.py` to generate concurrent case-creation load.

## Files of Interest

- `docker-compose.yml` defines the full stack.
- `config/thehive/application.conf` contains the TheHive and MISP integration settings.
- `scripts/bootstrap_thehive.sh` checks connectivity and prints the remaining manual steps.
- `scripts/submit_alert.py` sends a JSON alert into TheHive.
- `scripts/perf_load.py` creates a small concurrent load test.
- `backup/backup_thehive.sh` creates a backup archive of persistent data.

## Notes

This scaffold follows the same pattern as the other labs in the repository: environment-driven configuration, local volume mounts, and small helper scripts for the common demo flows. The TheHive MISP API key still has to be copied in after the first MISP login because the API key is generated by the running service.
